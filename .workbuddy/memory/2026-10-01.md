## 植物卡 tooltip #1009（已修复）

- 报错：`PlantCardToolTipMediator/updateSelfBattleCardByPosInfo` → #1009。
- 反汇编 `ModuleBattleLineup.swf` 的 `PlantCardToolTipWithAllMediator.changeHandler`：
  tooltip 载荷按**类型**分四路 —— `CardItemVO`→update / `Dto_CardPosInfo`→
  **updateSelfBattleCardByPosInfo**（查**玩家自己**的卡） / `Dto_FriendInfo`→updateHelpBattleCard /
  `Dto_EnemyCardInfo`→updateEnemyBattleCard（敌人卡的安全路径）。
- 根因：`handle_rankarena_getformation` 在挑战后返回**机器人**的阵容
  （`build_formation_info(bot_player, 3, placements)`）。`Dto_FormationInfo` 里是
  `Dto_CardPosInfo`，槽位 uid 是机器人的卡——玩家集合里没有 → `updateSelfBattleCardByPosInfo`
  查空 → #1009。
- 修复：该 handler 改回**只发玩家自己的阵容**（`_arena_getformation(player, 3, sc)`，与普通
  竞技场同一路径）。对手阵容本就通过开打前预览的 `Dto_EnemyCardInfo` 下发，走的是安全路径。
- 验证：`Cmd_RankArena_GetBattleFormation_SC`/`GetDefenseFormation_SC` 均由
  `default_formation_placements(player)` 构建，6 个槽位 uid **全部属于玩家自有集合**。

### 不变量（务必遵守）
**`Dto_FormationInfo`/`Dto_CardPosInfo` 只能装玩家自己的卡牌 uid**（tooltip 会按 uid 查玩家集合，
查不到即 #1009）；要展示别人的阵容/敌人，必须走 `Dto_EnemyCardInfo`（enemyCard 字段）。
全仓 `build_formation_info(...)` 调用点已审计，现在全部传 `player`。


## 世界boss：boss 显示成僵尸 + 相同类型控制器只能添加一次（已修复）

- 报错：`UnitBase/addControl → UnitFactory/updateUnit → UpdateUnitPlan/doPlan`
  `Error: 相同类型控制器只能添加一次!`，且用户看到"boss 变成僵尸了"。
- 两个根因，同源于我加的陵墓护卫：
  1. **posIndex 冲突**：boss 自己站 `_ENEMY_POS[0]`(pos 4)，护卫也用 `_ENEMY_POS[i % 7]`
     → 护卫[0] 也是 pos 4。客户端 UnitFactory 对同一格只建一个单位，护卫数据把 boss 覆盖
     → boss 看起来"变成僵尸"；同一单位被二次 update → `addControl` 抛"相同类型控制器只能添加一次"。
  2. **boss 身份**：`battleCard` 里 `999=邪恶博士`、`998=秦始皇`、`1000=霸刀将王`。WorldBoss.txt
     的官方顺序是 邪恶博士(order1)→秦始皇(order2)→霸刀将王(order3)，本地把 999 放第一位，
     玩家看到的"第一个 boss"就是邪恶博士（一个僵尸反派），被当成"boss 变成僵尸"。
- 修复：
  - `_worldboss_escort_units` 改用 `slots = [p for p in _ENEMY_POS if p != _ENEMY_POS[0]]`
    （护卫永不占 boss 的格子）。
  - `_WORLD_BOSS_IDS = (998, 999, 1000)` + `_WORLD_BOSS_DEFAULT = 998`，三处
    `get(1, 999)` 默认值改为 `_WORLD_BOSS_DEFAULT` → 默认/首位 boss = 秦始皇。
- 验证：boss 998=秦始皇(pos4)，护卫 pos=[8,10,12,14]（顶碗军士/弓箭/推车小贩/骑兵），
  位置无冲突 True；秦始皇 FightInfo 预览 724B。

### 不变量
**同一场战斗的 rightSide/enemyCard 里 posIndex 必须互不相同**（含 boss 与护卫/召唤物）；
一个 posIndex 一个单位，重复会让客户端 UnitFactory 覆盖显示并抛"相同类型控制器只能添加一次"。


## 更正：世界boss 开局没有小怪，大招才召唤（已按用户澄清重做）

- 用户澄清：**开局场上只有秦始皇本尊，没有小怪**；大招时才随机召唤 4 只秦始皇陵小怪。
  之前"护卫随 boss 一起入场"的实现方向错了，已回退（护卫代码删除）。
- 查证回放协议：`E_FightActionType` 只有 `Attack(0)/Update(1)`，`Dto_FightActor` 按
  actorIndex 引用 beforeCardList 里**预先存在**的单位 —— **回放格式表达不了"中途生成新单位"**。
  所以"4 只小怪凭空出现"在纯服务端做不到，需要改客户端 SWF。
- 现实现（协议能表达的最接近形式）：`_worldboss_ultimate(rounds, boss_pos, entry)` 在
  **第 3 回合**给 boss 注入一条 action —— `skill=2`（施法动画）+ 大量回血（dmg<0 → changeHp
  为正，绿色治疗数字）+ `buff_id=1, is_add_buff=True`（buff 图标）。视觉上就是 boss 释放大招
  强化自身。轮次结构是 `(actions, buffs)` 元组，注入时重建该元组。
- 验证：开局敌方单位=1；回放 7 轮；第 3 回合 action actor(pos)=4、skill=2、回血 416,601、
  is_add_buff=True；战报 3549B。`py_compile` 通过。
- 若要真正"看到 4 只小怪被召唤出来"，需要客户端补丁：在 UnitFactory/回放树里支持
  一个新的 E_FightActionType（如 Summon）或允许 Update 引用 beforeCardList 之外的新 actorIndex。

## EXE 打包完成：PvZOnline.exe + PvZServer.exe（免 Python 免 Flash）

  - **PvZOnline.exe**（onefile 无窗口 GUI，13.6MB）= launcher.py 打包，双击即用；
  - **PvZServer.exe + _internal/**（onedir 控制台）= run_all.py 打包，launcher 用 CREATE_NO_WINDOW 隐藏窗口调用并 PIPE 日志。
- **路径布局关键**：服务器模块全部 `__file__` 相对定位（`../webroot`、`../Assets`），PvZServer.exe 必须放
  **游戏根目录**（其 `_internal` 的父目录=根目录）→ 所有路径自动成立，服务器零改动。
- **players.db 统一迁到根目录**（两个 exe 共享）：player_store/guild_local/missing_features_local/
  main_quest_local 四处 DB 路径改为 frozen 感知（`sys.frozen` → dirname(sys.executable)）；
  player_store 首次运行自动从 `PvZ-Server-PoC/players.db` 复制迁移（实测 897KB 迁移成功）。
- gm 打进 PvZOnline.exe：launcher._run_gm frozen 分支改为**进程内调用** gm.main()（argv 替换 +
  redirect_stdout + SystemExit 捕获）；gm._clientdb_dicts 的 clientDB 路径 frozen 感知（根目录/webroot）。
- `Play PvZ Online.bat`：存在 PvZOnline.exe 就直接启动，否则回退 python launcher.py。
- **代理坑（重要）**：本会话 Bash 沙箱注入 `HTTP_PROXY=127.0.0.1:3196`，Ruffle 继承后加载
  127.0.0.1:8080 被 502；清掉代理变量后沙箱又干扰 DNS（"Domain resolution failure"）——
  **两者都是沙箱伪象，真实桌面 Ruffle 直连正常（12:31 已证）**。已给 launcher 加 `game_env()`：
  剥掉全部代理变量 + 设 NO_PROXY=127.0.0.1,localhost，对播放器进程生效（防玩家环境有代理）。
- 实测：PvZServer.exe 三端口+HTTP 200+存档迁移 ✅；PvZOnline.exe GUI 渲染+播放器下拉框 ✅（截图 gui.png）。
