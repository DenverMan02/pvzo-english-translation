## 性能优化：进游戏（登录链路）提速

- **定位**（server_runtime.log 时间线 + cProfile）：`Cmd_Card_GetPackage` 处理 118 张卡耗时 27~38s（每次登录都慢，两次会话复现）；`Cmd_Battle_GetFormation` 2s；惰性模板加载 2~3s。GetBuildingEvent 后的 ~27s 空档是客户端本地行为（上次会话同位置空档 2 分钟），不是服务器问题。
- **根因**：`player_store._db()` 每次 `sqlite3.connect`/close（一次 GetPackage 开 ~15k 连接，8.5s 纯连接开销）+ `_armor_growth` 在卡循环里每卡重算（内部 `get_item_count` 逐晶体查询 40 次/卡）+ `_avatar_default_status` 每个时装查一次 `get_card_avatars`/`get_card_fill_quality`（~34 查询/卡）。
- **修复**：
  1. `player_store._db()` 改**每线程复用连接**（`_THREAD_STATE` + DB_PATH 变化自动断开旧连接 + 异常 rollback）；新增 `set_db_path()`/`close_thread_db()`。
  2. `handle_card_getpackage`：`_armor_growth`/cards_by_uid/avatar 状态字典循环外一次预取，经 `_growth`/`_cards_by_uid`/`_shared` 参数透传（`_apply_armor_bonus`/`_avatar_default_status`/`_card_avatar_*`/`_card_power_source_elements` 均加可选参数，默认 None 走旧路径）。
  3. `_warm_up_templates()`：启动时预热 32 个惰性 clientDB loader（幂等缓存），放 `main()` 里 `_seed_bots()` 后。
- **效果**：GetPackage 27~38s → **0.116s**；GetFormation 2s → 0.028s；响应字节与优化前逐字节一致（11975/1146）。登录服务器侧耗时 ~30s → <0.5s。
- **测试适配**（连接保持打开会卡住 Windows 删临时目录）：test_gene_6_10(tearDown 加 close)、test_missing_features(addCleanup LIFO 两个模块对象都关)、test_nutrition_actions/supertrade_errors/wardrobe_purchase(with 块尾加 close)、test_skill_effects(finally 加 close)、test_combat_crit_dodge(mock lambda 改 `*a, **k` 接受新 kwargs)。回归 46 用例 failures=4/errors=7 基线不变。
